# AI-native 学习产品参考索引

> 建档日期：2026-09-02<br>
> 作用：记录参考产品的已验证事实、产品判断和 Stair 的取舍。<br>
> 当前状态：产品研究，不代表功能已经实现。

## 为什么建立这份索引

这些产品不是一张待抄写的功能清单，而是分别解决学习闭环中的不同问题。本索引用来防止两种偏差：

- 看到一个好功能就增加一个入口，最终把产品做成 AI 工具箱；
- 把厂商描述、我们的判断和已经实现的能力混在一起。

每份档案都遵守同一规则：

1. **产品事实**必须来自官网、官方文档或固定版本源码；
2. **产品判断**说明它为什么有效、可能在哪里失效；
3. **借鉴决策**只回答 Stair 应吸收什么、重写什么、拒绝什么；
4. **实现状态**另行跟踪，不能因为写入档案就视为已经进入产品。

## 五个产品分别贡献什么

| 参考产品 | 在学习闭环中的职责 | 最值得吸收的机制 | 主要风险 | 详细档案 |
|---|---|---|---|---|
| Socratopia | 引导理解与高频 Process | 教材锚定的连续追问；用户刚才的回答决定下一步；伙伴提供可选的情绪连续性 | 没有必要输入就先追问会变成猜题；微输出顺畅不等于能完整独立输出 | [Socratopia](./socratopia.md) |
| DeepTutor | 持久学习路径与多能力编排 | 统一运行时和上下文；学习状态独立于聊天；待答动作可恢复；编排器只推荐一个下一步 | 能力与入口膨胀；Probe First、百分比分数和平台复杂度会增加用户负担 | [DeepTutor](./deep-tutor.md) |
| MyLens | 将复杂关系外化为可操作的视觉模型 | 按信息结构选择时间线、导图、流程图等视图；局部解释、来源定位和继续展开 | AI 画出的漂亮结构不等于用户自己的心智模型 | [MyLens](./mylens.md) |
| ThetaWave | 以同一来源贯穿多个学习动作 | 一份来源只导入一次；笔记、问答、练习和整体视图共享上下文；低门槛短练习 | 一键生成整套笔记、导图、播客和闪卡，会把 Input 膨胀得更快 | [ThetaWave](./thetawave.md) |
| Zettelkasten Second Memory | 长期保存、连接与唤醒“我的理解” | 原子理解、来源追溯、语义关系、候选关联、旧理解的任务相关检索 | Agent 自动整理出的知识不是用户挣得的理解；图谱密度也不是掌握 | [Zettelkasten Second Memory](./zettelkasten-second-memory.md) |

## 能力拼图

```text
资料进入
  │  ThetaWave：同一 Source 与上下文连续
  ▼
Learn First
  │  Socratopia：短讲解后，以回答驱动追问与反馈
  │  MyLens：用合适的视觉支架建立整体模型
  ▼
有支架处理
  │  DeepTutor：按知识类型选择解释、回忆、操作或设计
  ▼
AI 交棒并沉默
  │  Stair：用户独立说 / 写 / 画 / 做，保存原始 Attempt
  ▼
反馈与 Repair
  │  Stair：比较原始理解、帮助和修正，不替用户覆盖答案
  ▼
延迟回忆与真实项目
  │  DeepTutor：可恢复路径与到期任务
  │  Zettelkasten：唤醒旧理解及其关系
  ▼
能力证据
     Stair：独立完成、延迟仍会、跨情境应用
```

五个产品各自提供一块能力，但 **Stair 的独特价值是闭环编排**：

> 在恰当时机给必要输入，尽快让用户处理；随后逐步撤掉 AI 支架，迫使完整独立输出；再用反馈、延迟回忆和真实迁移建立可追溯的能力证据。

## 核心产品路线

对于用户第一次学习的新主题，默认主路径不是 Diagnosis First，也不是一上来让用户画图，而是：

```text
Learn First
→ 有支架练习
→ 独立输出
→ 反馈与修正
→ 延迟回忆
→ 新情境迁移
```

只有两种情况可以先挑战或诊断：

- 用户明确说自己已经学过，希望复习或查漏；
- 系统已有可信的历史学习证据，且用户愿意跳过讲解。

视觉外化也遵守相同次序：首次导入后，AI 可以先给局部示范或待补全的骨架；用户获得必要理解后，再让他重建、补全、纠错或从空白画出自己的模型。AI 自动生成的完整图只能是参考视图，不能成为掌握证据。

## 映射到 Stair 六个入口

我们不为五个参考产品分别增加入口。复杂能力藏在后台，前台六个入口保持完整、自然且可预期。

| Stair 入口 | 用户来这里做什么 | 主要参考 | 设计取舍 |
|---|---|---|---|
| 首页 | 接着上次的具体学习动作 | DeepTutor、Socratopia | 首要动作永远是“继续上次”，恢复来源、阶段、待答动作和草稿；不是泛化 Dashboard，也不是模式选择器 |
| 学习 | 从不会到初步理解，再逐步接过认知权 | Socratopia、MyLens、DeepTutor | 新主题 Learn First；讲解、示例、视觉支架和追问由当前回答决定，达到条件后必须交棒 |
| 练习 | 闭卷回忆、解释、操作或设计 | ThetaWave、DeepTutor | 用 3/5/10 分钟降低启动成本；先提交再反馈，并保留 Attempt、帮助和 Repair，不只留下分数 |
| 项目 | 在真实约束下做出作品或决策 | DeepTutor | 复用同一材料和旧理解；AI 可以辅导，但真实产物、取舍和结果才是迁移证据 |
| 资料 | 导入、阅读、定位和追溯来源 | ThetaWave、MyLens | 一份资料只有一个 Source；选中内容后快速进入解释、提问或小输出，不默认批量生成六套产物 |
| 成长 | 看见能力如何从有支架走向可迁移 | Zettelkasten、DeepTutor | 展示理解版本和行为证据；不展示生成物数量、图谱密度或单一掌握百分比 |

“直接问 AI”是所有入口中的上下文动作，不需要成为第七个一级入口。AI 知道用户正在看的来源、学习阶段和当前草稿，但回答方式受所在阶段约束。

## 跨产品后的统一产品原则

### 1. AI 生成物不等于学会

总结、笔记、导图、闪卡、测验、播客和路线都只是支架或候选材料。只有用户自己的行为能更新能力状态。

### 2. 去掉的是事务摩擦，不是认知摩擦

AI 应自动承担导入、切片、检索、定位、排程、格式转换和上下文恢复；解释、回忆、推理、取舍、创作和迁移必须尽可能由用户完成。

### 3. 来源、我的理解、能力证据是三个对象

```text
来源：作者、资料或 AI 说了什么
我的理解：我当前如何解释、连接和修正
能力证据：我能否在不同帮助程度、时间和情境下完成
```

三者可以互相追溯，但不能互相冒充。

### 4. 一个时刻只有一个明显主动作

系统内部可以调用 Tutor、Quiz、Research、Visualize、Memory 和 Scheduler；用户看到的是“现在最值得做的一步”，以及少量完整但次级的替代入口。

### 5. 继续的不是聊天，而是学习状态

“继续上次”必须恢复到具体来源、概念、阶段、未提交 Attempt 和草稿。换会话、换教学表达或重新打开产品，都不能让学习路径丢失。

### 6. 帮助要逐步撤掉

产品不只追求“在 AI 陪伴下做对”，还必须设计交棒：从示范、提示和追问，过渡到 AI 沉默下的完整输出。

### 7. 掌握要经过时间和迁移

一次课堂回答或一次测验正确只能证明当时表现。能力至少区分：

```text
正在学习
→ 在支架下完成
→ 当前能独立完成
→ 延迟后仍能完成
→ 能在新情境中应用
```

## 明确不抄什么

- 不把 Chat、Quiz、Research、Solve、Visualize、Mastery 等后台能力平铺成首页工具箱。
- 不以 Diagnosis First 或 Probe First 作为新主题默认流程。
- 不要求刚导入、尚未学习的用户先完整画图、解释或证明。
- 不默认把每份资料生成总结、导图、播客、闪卡和测验全家桶。
- 不把伙伴、世界观或游戏化配置变成开始学习的前置步骤。
- 不把 AI 自动画出的关系图写入“我的理解”。
- 不把学习时长、对话数、生成物数、笔记数、图谱密度或路线百分比叫作成长。
- 不用一次 LLM 判断、字符串评分或厂商自报效果宣布用户已掌握。
- 不让 AI 在用户尝试前泄漏参考答案，也不让修正覆盖原始 Attempt。
- 不新增“第二大脑”维护工作，把整理知识库的负担重新交还用户。

## 后续设计如何使用这些档案

每次提出新功能时，依次回答四个问题：

1. 它补的是 Input、Process、Output、反馈、记忆还是迁移中的哪一段？
2. 它是否让用户更早产生自己的认知动作，还是只生成了更多可消费内容？
3. 它应该成为新的用户入口，还是由已有入口在恰当状态下自动调用？
4. 它将留下什么行为证据，怎样与来源和 AI 帮助区分？

如果这四个问题没有明确答案，就不因为某个参考产品有此功能而加入。
