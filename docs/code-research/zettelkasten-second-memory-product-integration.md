# Zettelkasten Second Memory 融入 Stair 的产品设计

> 研究日期：2026-09-01<br>
> 上游仓库：[`cx2002302-lang/zettelkasten-second-memory`](https://github.com/cx2002302-lang/zettelkasten-second-memory)<br>
> 固定版本：[`731b58836e2c579dd8cba126b2c092ad5984d8d6`](https://github.com/cx2002302-lang/zettelkasten-second-memory/tree/731b58836e2c579dd8cba126b2c092ad5984d8d6)（`v1.0.0-beta.8`）

## 结论

这个项目值得融入，但不应被作为一个新的“双链笔记”产品入口，也不建议直接把当前插件当作 Stair 的学习内核。

它真正补齐的是现有学习闭环中缺失的一层：**“资料”与“能力证据”之间，属于学习者自己的、可以持续修正和重新调用的“我的理解”。**

产品原则可以压缩为一句话：

> AI 消除整理、检索和关联的机械摩擦；学习者保留回忆、解释、判断和应用的认知摩擦。

## 一、上游项目实际提供了什么

上游定位是 OpenClaw / Hermes Agent 的持久知识基础设施，而非面向学习者的教学产品。其公开能力包括三类笔记、11 类语义链接、SQLite FTS5 检索、对话蒸馏、标签、归档、Glow 排名、Zombie 检测和路径发现。[README](https://github.com/cx2002302-lang/zettelkasten-second-memory/blob/731b58836e2c579dd8cba126b2c092ad5984d8d6/README.zh.md#L34-L50)

核心数据模型把笔记分为 `atomic / structure / source`，生命周期为 `FLEETING / LITERATURE / PERMANENT`，并以 `supports / refines / extends / contradicts / example` 等语义关系连接。[类型定义](https://github.com/cx2002302-lang/zettelkasten-second-memory/blob/731b58836e2c579dd8cba126b2c092ad5984d8d6/src/core/types.ts#L1-L65)

其 CEQRC 流程是 `Capture → Explain → Question → Refine → Connect`。但实现中五个阶段均交给 LLM 处理；连 “in your own words” 也是写给模型的提示词，不是要求学习者自己解释。[CEQRC 实现](https://github.com/cx2002302-lang/zettelkasten-second-memory/blob/731b58836e2c579dd8cba126b2c092ad5984d8d6/src/service/ceqrc-engine.ts#L28-L127)

对话蒸馏会切分会话、生成摘要、去重，并根据模型决策创建、合并或跳过笔记；建议链接也可以被自动写入。[蒸馏实现](https://github.com/cx2002302-lang/zettelkasten-second-memory/blob/731b58836e2c579dd8cba126b2c092ad5984d8d6/src/service/distiller-service.ts#L65-L113) [自动建卡与建链](https://github.com/cx2002302-lang/zettelkasten-second-memory/blob/731b58836e2c579dd8cba126b2c092ad5984d8d6/src/service/distiller-service.ts#L314-L345)

仓库里的 Review 是对笔记、链接、标签或系统结果做 `approve / reject / modify / flag` 的内容审核，不是先隐藏答案、再要求学习者回忆的学习复习。[审核文档](https://github.com/cx2002302-lang/zettelkasten-second-memory/blob/731b58836e2c579dd8cba126b2c092ad5984d8d6/skills/brain/docs/06-review-feedback.md#L18-L62)

“前台聊天只读、后台知识 Agent 读写”的权限分离很值得借鉴：聊天 Agent 只能搜索、读取、查看反链和路径，知识 Agent 才能创建、更新、连边和蒸馏。[权限模型](https://github.com/cx2002302-lang/zettelkasten-second-memory/blob/731b58836e2c579dd8cba126b2c092ad5984d8d6/src/integration/agent-config.ts#L84-L135)

当前版本仍更适合作为机制参考，而不是直接依赖：插件初始化为 CEQRC 和蒸馏注入的是会抛出“未配置”错误的空 LLM Provider；注册的 `session_end` 处理也只记录日志。[插件生命周期](https://github.com/cx2002302-lang/zettelkasten-second-memory/blob/731b58836e2c579dd8cba126b2c092ad5984d8d6/src/plugin/lifecycle.ts#L38-L79) [Session Hook 边界](https://github.com/cx2002302-lang/zettelkasten-second-memory/blob/731b58836e2c579dd8cba126b2c092ad5984d8d6/src/plugin/lifecycle.ts#L126-L151)

## 二、为什么不能原样照搬

上游的目标是让 **Agent 以后找得到信息**；Stair 的目标应是让 **人以后能独立想起并用出来**。两者不能用同一套成功标准。

如果直接照搬，流程会变成：

```text
资料 / 对话 → AI 解释 → AI 提问 → AI 精炼 → AI 连边 → 用户得到漂亮知识库
```

这会把用户的 Input 变成更多由 AI 生产的 Input。用户自己的组织、回忆、表达和应用仍然没有增加。

尤其不能混淆以下三件事：

| 问题 | 正确的数据层 | 能否说明“学会了” |
|---|---|---|
| 资料是否可靠、来自哪里 | 来源记忆 | 不能 |
| 用户目前怎样理解 | 我的理解 | 仍不能单独说明 |
| 用户能否无辅助回忆并迁移 | 能力证据 | 可以形成分阶段结论 |

上游的 `confidence` 适合表达内容或自动路由的信心；它不应该被复用成学习者掌握度。笔记数、链接数、PageRank、搜索命中率和图谱密度也只能反映知识库状态，不能证明学习效果。

## 三、产品中的三层记忆

### 1. 来源记忆

保存原文、网页、视频、对话、AI 摘要和精确引用。AI 可以自动切分、去重、标注和检索，但这些内容只代表“系统见过”。

回答的问题是：**根据什么？**

### 2. 我的理解

保存学习者自己的解释、例子、反例、问题、模型和关系说明。AI 可以根据用户刚才的输出提出草稿，但必须显式标注“AI 帮你整理”，并由用户修改或确认后才进入这层。

回答的问题是：**我现在怎么理解？**

### 3. 能力证据

保存原始 Attempt、使用过的帮助、反馈、修正、延迟回忆和项目迁移。它不复制“我的理解”，而是给理解附上行为证据。

回答的问题是：**我真的能做到吗？**

三层互相引用，但绝不合并成一个分数。

## 四、重写后的学习闭环

```text
资料 / 对话
    ↓
Learn First：AI 讲解、示例、互动探索
    ↓
有支架练习 → 交棒 → 用户独立输出
    ↓
反馈 → 用户修正
    ↓
“留下这次理解”（用户确认）
    ↓
AI 建议一次有意义的旧知识连接
    ↓
延迟闭卷重建 → 新情境应用
    ↓
更新“我的理解”版本与能力证据
```

Zettelkasten 不发生在导入之后，而发生在**用户真正完成了一次理解或应用之后**。它是闭环的结晶层，不是新的输入层。

## 五、标志性交互

### 交互 A：留下这次理解

在现有 `反馈 → 修改方案 → 成长证据` 之间插入一个自然时刻：

> 把这次真正学会的，留给未来的自己。

系统基于用户的原始 Attempt 和 Repair 生成一张草稿：

```text
我的理解
召回只说明记忆可能相关；使用前仍需判断时效、冲突与可信度。

我原来遗漏了
把召回结果直接用于回答。

依据
我的原始方案、修正版、两处来源引用。
```

操作只有三个：`留下`、`改一下`、`这次不留`。没有标签、文件夹和卡片 ID。

### 交互 B：过去的你

下一次复习或真实任务遇到相关问题时，先隐藏旧卡正文，让用户写、说或画出当前理解；提交后再揭示：

- 你今天怎样解释；
- 过去的你怎样解释；
- 哪部分稳定了，哪部分改变了，为什么。

这把长期记忆从“检索答案”变成主动回忆与认知版本对比。

### 交互 C：桥接挑战

AI 可以在后台发现潜在链接，但不直接宣布关系成立，而是问：

> “使用判断”和你以前学过的“冲突解决”有什么关系？

用户先回答，AI 再反馈。用户的关系说明才成为边的上下文。路径发现和 Serendipity 由此从图谱展示变成一次迁移练习。

## 六、进入现有产品的位置

不增加“第二大脑”或“Zettelkasten”一级入口，保留：首页、学习、练习、项目、资料、成长。

| 入口 | 融入方式 |
|---|---|
| 首页 | 仍优先“继续上次”；恢复具体学习、未完成输出或到期回忆，不出现笔记 Inbox 待办 |
| 学习 | 新主题坚持 Learn First；AI 静默读取已确认的旧理解用于举例，学习完成后才出现“留下这次理解” |
| 练习 | 隐藏“我的理解”正文，要求先重建、举反例或解释关系；提交后才揭示旧版本 |
| 项目 | 先让用户做出初步判断，再按需唤起相关理解；应用结果回写为例子、反例或迁移证据 |
| 资料 | 继续管理原始来源；资料详情显示“由此形成的我的理解”，可在二级筛选查看 |
| 成长 | 展示从支架下完成、独立完成、延迟后仍能完成到新情境应用的证据，不展示图谱虚荣指标 |

全局搜索和“问 AI”同时搜索三层，但回答必须显式区分：

> 资料原文认为……<br>
> 你过去的理解是……<br>
> 你最近一次实践发现……

图谱只能作为“我的理解”里的可选关系视图，不能成为首页、一级导航或默认工作方式。

## 七、AI 权限与写入规则

借鉴上游前台只读、后台读写的模式，但增加用户所有权门槛：

1. **教学 AI**：可以读取来源、已确认理解和能力证据；不能静默改写“我的理解”。
2. **记忆整理 AI**：可以生成候选卡、候选关系、去重和版本差异；只能写入候选区。
3. **用户确认**：把候选晋升为“我的理解”，或拒绝、修改、标记矛盾。
4. **证据记录器**：只从真实 Attempt、帮助使用、延迟和迁移结果写能力证据；AI 生成文本不得计入。

因此，资料可以自动进入系统，理解只能由用户挣得，掌握只能由行为证明。

## 八、最小但完整的第一版

只实现一条纵向闭环：

1. 在 Repair 后新增“留下这次理解”。
2. 草稿只从用户的 Attempt、Repair 和来源引用生成，并允许编辑或跳过。
3. 最多推荐一个旧理解，让用户补一句“为什么有关”。
4. 下一次到期练习先闭卷重建，再揭示“过去的你”。
5. 把本次结果追加为能力证据和理解版本，不计算抽象掌握分。
6. 资料详情显示它形成了哪些“我的理解”；全局搜索明确区分资料、理解和证据。

第一版明确不做：

- 新的一级入口；
- 独立知识图谱首页；
- 11 种面向用户的链接类型；
- 标签、Inbox、Zettels、References 等维护负担；
- 夜间自动生成大量永久卡片；
- Glow、Zombie、链接密度等学习成就；
- 用户尚未学习时要求画图、拆卡或建立关系。

## 九、验证指标与失败反例

北极星指标：

> 每单位学习时间，在延迟后仍能无辅助重建，并能在新问题中正确应用的理解数量。

辅助指标：

- 从开始学习到第一次独立输出的时间；
- 学习单元产生用户输出的比例；
- 2 天、7 天、30 天无提示回忆成功率；
- 新情境迁移成功率；
- 永久理解中来自用户输出的比例；
- 用户花在审核、标签和清理上的时间；
- AI 候选卡与候选关系被修改或否决的比例。

出现以下任一情况即判定融合失败：

- AI 从一份资料生成大量卡片和链接，但用户第二天不能解释核心概念；
- 用户点击“保存 AI 总结”后，系统就宣称已掌握；
- 未学过的导入资料进入“我的理解”或“成长”；
- 复习先显示旧卡，再让用户确认“记得”；
- 用户维护标签和图谱的时间超过实际练习时间；
- 新主题在教学前要求用户拆卡、画关系或接受诊断。

## 十、对现有原型的具体改动建议

现有黄金链路可以保持不变，只增加两个视图：

```text
继续上次 → Learn → 有支架练习 → 交棒 → 独立输出
→ Feedback → Repair → 留下这次理解 → 成长证据
```

以及下一次进入时的：

```text
首页 70 秒唤醒 → 闭卷重建 → 揭示过去的你 → 认知差异 → 更新证据
```

这已经能验证最关键的产品假设：**当个人知识网络成为学习输出的自然副产品，而不是额外的整理任务时，能否提高延迟回忆与迁移，同时不增加理解成本。**
