# Stair 阶段 0—4 功能等价审计计划

## 研究目标

本次研究回答一个问题：从旧 Stair 分支重写到当前阶段 0—4 后，哪些变化只是架构收敛，哪些变化实际改变、删除或推迟了用户可见功能。

## 对比基线

- 旧版产品基线：`codex/rebuild-thinking-agent@6dc6c9fb`。
- 旧版 Workbench 参考：`codex/stair-workbench-checkpoint@6be3dd4b`。
- 当前实现：`codex/stair-rebuild-v2@a6f66bd5` 加当前未提交的阶段 4 改动。
- `promo/`、阶段 5 之后尚未开始的实现，以及用户无关改动不纳入代码修改范围。

## 分类规则

1. **已确认回归**：当前阶段宣称保留，但实际用户行为与旧版不一致。
2. **明确延期**：旧版已有，但重建计划明确放在阶段 5 以后；从阶段交付看不是误实现，从完整产品看仍是能力缺口。
3. **等价替换**：实现或数据边界改变，但用户能力保持一致。
4. **安全收窄**：为了资源、安全或确定性主动增加限制，需要确认是否可接受。
5. **待确认**：源码证据不足，必须由真实 UI 或产品决策确认。

## 验证方法

- 对比 Git 历史、旧版源码、当前源码和阶段计划。
- 为已确认的 EPUB 窄屏目录回归先增加失败测试，再最小修复。
- 分别调用 Claude 和 Kimi 对相同基线进行独立分析。
- 运行聚焦测试、Electron 类型检查和真实 Electron UI 验证。

## 研究结果摘要

- EPUB 窄 Panel 目录挤压正文已按旧版 840 px 边界最小修复。
- 确认两项 P0 运行时回归：HMR React Root 不复用，以及 WindowManager 未过滤 EPUB 子框架/`ERR_ABORTED` 的加载失败。
- 确认 Draft Workspace 授权、空 Session 清理、PDF 窄栏、Markdown 链接等阶段 0—4 行为缺口。
- Project Files 搜索/创建/图片、Save Draft As、Reader pageLabels/导出/分组等旧能力没有被现有计划承接。
- 阶段 5—9 的明确延期与上述意外回归已经分开记录；不建议在等价性收口前进入阶段 5。
