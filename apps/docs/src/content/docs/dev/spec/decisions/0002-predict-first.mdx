> **状态**：提议

## 背景

之前的产品原则是"新主题先讲（Learn First），不先挑战"，理由是拒绝参考产品中"先测验再教"的做法。复核学习科学证据后发现，这条原则把两件不同的事混在了一起：

| | 诊断测验 | 预测问题 |
|---|---|---|
| 目的 | 判断会不会，用于分流 | 让大脑形成预期，为讲解做准备 |
| 是否计分 | 是 | 否 |
| 用时 | 几分钟 | 一分钟以内 |
| 证据 | 没有学习收益，有焦虑成本 | 即使答错，也能提升随后对该内容的学习（B+） |

## 决定

- 不做分流式诊断测验。
- 新主题默认先问一两个不计分、可跳过、一分钟内能答的预测问题，讲解引用用户的猜测。
- 概念性内容可以选用"先尝试、后讲解"；程序性技能的新手改为样例先行。

## 理由

预测问题成本很低，同时带来三点好处：讲解时产生"原来如此"的对比；适度的不确定激发好奇；用户的猜测本身就暴露了他的直觉模型，讲解可以直接针对它，不需要另做诊断。

## 影响

- 修订[设计原则 5](/dev/spec/principles/#p5)。
- 新增功能[先猜一下](/design/learn/prediction/)。
- 风险：预测环节跳过率超过一半时需要回头调整问题设计。
