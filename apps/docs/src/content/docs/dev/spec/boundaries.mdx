参考其他学习产品时，最容易犯的错是"别人有，我们也加一个"。这一页列出明确不做的事。每一条都写了为什么，以及换成什么做法。

| 不做 | 为什么 | 改为 |
|---|---|---|
| 把总结、测验、研究、导图等能力排成首页工具箱 | 把策略选择交给了最不擅长选择的人。学习者天然偏好重读和看总结 | 一次推荐一步并说明理由，其他选项可选（[原则 4](/dev/spec/principles/#p4)） |
| 开始学一个新主题前先做摸底测验 | 分流式诊断本身没有学习收益，还增加焦虑 | 讲解前问一两个不计分的直觉问题，这本身就是学习（[原则 5](/dev/spec/principles/#p5)） |
| 要求还没学的人先完整画图、解释或证明 | 对新手是认知过载 | 第一步永远是一句话：一个猜测、已知的一点，或学它的原因 |
| 每导入一份资料就生成总结、播客、导图、闪卡、测验全家桶 | 总结、播客和现成导图是"可消费的输入"，效果接近重读，还会制造"我懂了"的错觉 | 消费型的只在用户主动要时生成，标为参考；问题和闪卡这类检索型的按进度生成，且必须先作答才能看答案 |
| 用积分、排行、连续打卡来换学习行为 | 可预期的外在奖励会削弱内在动机；游戏化的效果不稳定 | 用真实的能力证据给反馈；AI 可以扮演需要你讲给它听的新手 |
| 把伙伴、角色、世界观设成开始学习的前置步骤 | 增加启动成本，和学习本身无关 | 不做前置；如以后做，只能是可选项 |
| 让未经用户加工的 AI 产物进入"我的理解" | 会让 AI 的理解冒充用户的理解 | 按作者权记录：用户原创、用户改过的 AI 草稿（附修改比例）、AI 原文；只有前两种算"我的理解"（[决策 0004](/dev/spec/decisions/0004-authorship/)） |
| 把时长、对话数、笔记数、图谱密度叫作成长 | 它们衡量投入或产量，不是能力 | 投入和成长分开展示；每次学习结束至少展示一条当场的真实证据 |
| 用一次 AI 判断宣布"已掌握" | 一次表现不代表长期能力；AI 评审有已知偏差 | 能力由多次、跨时间、跨情境的闭卷尝试推导，会衰减；AI 只按量规逐条评审并保留依据，用户可申诉（[决策 0005](/dev/spec/decisions/0005-evidence-levels/)） |
| 在用户尝试前给出答案，或者完全不给任何帮助 | 前者等于替用户做了，后者让人在原地空耗 | 分级提示，从"你卡在哪一步"到完整答案共五级，每一级都记在这次尝试上 |
| 用修正覆盖用户第一次的回答 | 丢掉了对比的基线 | 修正以新版本追加（[原则 11](/dev/spec/principles/#p11)） |
| 让用户打标签、归档、整理链接 | 这是文书工作，不是学习 | AI 承担全部文书型整理；用自己的话改写、说明两个概念的关系仍由用户完成，每次只要一句话 |
| 在同一次学习的末尾安排"延迟回忆" | 间隔太短，测的是短时记忆 | 第一次延迟回忆至少隔一夜（[原则 13](/dev/spec/principles/#p13)） |
| 按"视觉型、听觉型"等学习风格选择呈现方式 | 学习风格匹配没有学习收益，是神经迷思 | 按内容结构选视图：时间线、因果、层级各用合适的图 |
| 把用户觉得舒服当成学习功能的验收标准 | 有效的学习方法常常让人觉得更难 | 学习效果看回忆率和迁移率，满意度只用来监测流失 |
