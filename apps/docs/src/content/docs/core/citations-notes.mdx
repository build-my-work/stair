读到一半产生的想法，最容易丢在切换面板的那一刻。引用与笔记解决的就是这一步：选中即引用，引用可跳回。

## 三个动作

在任何内容来源里选中一段文字，都会看到同一组动作：

| 动作 | 做什么 | 落到哪 |
| --- | --- | --- |
| Add Chat | 把引用加进你选的那个会话的输入草稿 | 发送前还能改，布局不动 |
| New Chat | 用引用开一个新会话 | 新增一个 Auxiliary 面板 |
| Add Note | 把来源和完整选区追加进一篇 Markdown | 你选的笔记文件 |

支持的来源：正文文本、EPUB、PDF、内置浏览器网页、聊天消息和 Project 文件。目标选择列表里只出现当前 Project 的会话，归档或隐藏的不会出现；右键用户消息不会弹选区菜单——只有真正的选区才有动作。

## 引用可以跳回去

引用记录三样东西：所属 Project、原文、位置。点聊天里的引用预览，会打开来源面板并回到原始选区；同一个预览重复点击也一样，不需要重新挂载文件。

## New Chat 的原子性

New Chat 在点击时记下来源面板，异步创建完成后重新校验：来源还在，就在来源面板旁插入新面板，这个文件以后新建会话默认指向它；来源已被替换、关闭，或者你已经切到别的 Project，这次创建会整体回滚——不会留下空会话，也不会按过时的焦点位置插面板。

## 工作机制

引用从选中到进入会话，服务端会再校验一遍 Workspace、Project、会话归属和来源文件指纹。模型收到的是转义后的引用内容；输入框和聊天消息里只显示正文与引用预览，不显示内部数据。Add Note 的写入即使中途路径被换成符号链接，也出不了目标目录。

## 限制与说明

- Add Note 的目标记忆按 Project 隔离：重开应用仍记住上一次的目标，换 Project 互不复用；目标文件被删除后需要重新选择。
- 取消 Add Note 不会丢失当前选区，可以重新执行。
- 引用数量和序列化大小有服务端上限，超限的请求会被拒绝。
