[上一篇](/design/why/)讲了我希望解决的问题：输入多、输出少，问题问完就扔，在整体和局部之间迷路，工具把学习切碎，学没学会说不清。这一篇讲 Stair 打算怎样解决它们。

## Stair 想帮你做到的

Stair 是一个学习用的桌面工作台。它只想做好一件事：**让你学过的东西，真的变成你自己的。**

- **材料、笔记、AI 都在一个地方。** 读书时选中一段话，直接问 AI 或记进笔记，出处自动带上，点一下就能跳回原文。
- **AI 帮你干杂活，不替你动脑。** 找资料、定位原文、安排复习这些事交给 AI；用自己的话讲出来、回忆、想清楚为什么，这些留给你——因为只有这部分会留在你脑子里。
- **你能看见自己的进步。** 不是"学习时长 12 小时"这种数字，而是"上周你还需要提示，今天你不看书就讲清楚了"。

## 一次学习大概是这样的

周二晚上，你打开 Stair，它直接把你带回上次停下的地方：TCP 那本书的第 4 章，你写了一半的那段笔记还在。

开始学新的一节前，Stair 先问你一个小问题："网络突然变慢时，你觉得发送方应该怎么做？"你随手猜了一句。接下来的讲解会接着你的猜测讲——你猜对了哪一半，漏了哪一半。

讲完一小段，它请你用一句话说说"为什么"。卡住了可以要提示，从"你卡在哪一步"开始，一点点给。

学到差不多了，书暂时收起来，你试着把这一节讲给一个"什么都不懂的 AI 同学"听。它只会问"为什么""这是什么意思"，不会帮你答。讲完再对照原文，看看自己漏了什么。

第二天早上，Stair 提醒你花两分钟回忆一下昨晚学的内容。答出来了，这一节今天就结束了。

## Stair 是怎么组织的

Stair 围绕**一条学习主线**展开：读进来 → 想明白 → 讲出来、记得住 → 用得上。主线上的每一段，都有一个对应的**空间**；所有空间共用一个**底座**。

| 空间 | 你来这里做什么 | 现在 |
|---|---|---|
| [首页](/design/home/) | 从上次停下的地方接着学 | 在路上 |
| [资料](/design/sources/) | **读进来**：读书、论文和网页，选中就能问、能记 | 已经能用 |
| [学习](/design/learn/) | **想明白**：先猜一下，再一小段一小段地听 | 在路上 |
| [练习](/design/practice/) | **讲出来、记得住**：合上书讲一遍，隔天再回忆 | 在路上 |
| [实战](/design/apply/) | **用得上**：在新问题和真实任务里用出来 | 在路上 |
| [成长](/design/growth/) | 看见自己一步步的进步 | 在路上 |
| [工作台与 AI](/design/foundation/) | 底座：书、笔记、AI 并排，按主题分开 | 已经能用 |

完整的结构和每个功能的进度，见[产品全景](/design/map/)。

## 第一次用 Stair，从小处开始

不用一上来把所有资料都搬进来。**一个主题、一份资料、一个问题**就够了：

1. **新建一个学习主题**，比如"TCP"。
2. **放进一份资料**，一本书或一份 PDF 就行。
3. **带着一个问题去读**，比如"视频会议为什么会卡"。读到看不懂的地方，选中它，直接问 AI。

先这样用一次，再慢慢加。具体操作见[第一个 Project 与 Session](/start/first-project/)。
