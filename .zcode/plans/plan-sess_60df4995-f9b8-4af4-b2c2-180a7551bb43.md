# Stair 产品文档站实施计划（Astro + Starlight，zcode 风格）

## 目标形态

- `apps/docs`（包名 `@craft-agent/docs`）：Astro + Starlight 文档站，暗色默认、三栏应用壳（左侧分组导航 / 正文 / 右侧 On this page）、⌘K 搜索、中文优先。
- 参照 zcode 文档站：五组平铺 IA、每页统一写作模板、诚实的"限制与说明"、页尾"下一步"3 卡片。
- 本地预览（端口 5176），不配部署；内容纯产品向 + 架构分组；v1 截图用统一占位组件。

## 每页写作模板（zcode 式纪律）

痛点开场一句话 → 是什么 → 怎么用 → 覆盖什么/**刻意不做什么** → 工作机制（简） → **限制与说明**（诚实列表） → 下一步 3 卡片。每页 ≤800 字，段落 ≤3 句，用真实操作引语举例。

## 写作质量门禁（humanizer-zh 规则，方式 1 内联使用）

SKILL.md 与 16 类中文模式清单已完整加载，写每页时执行：

1. **保真约束**：所有数字、边界值、行为描述必须来自事实源（regression §4.6、模块 case、rebuild-plan），改写过程不许丢失限定条件和不确定度，不许编造细节充生动。
2. **自查信号簇**：空洞 praise、虚构权威、模板路标词（首先/其次/综上所述）、"不是…而是…"式假转折、三段式强迫症、赋能/抓手/闭环类抽象词、翻译腔长定语——按簇清除，不做单词级禁令。
3. **防矫枉过正**：保留必要的技术术语、安全提示、真实限定；产品文档该克制就克制，不装 casual。
4. **交付前终检**：事实/数字/引语是否原样、同段是否残留同类模式、语气是否符合产品文档文体。

## 实施步骤

1. **脚手架**
   - `apps/docs`：Astro + @astrojs/starlight，`defaultTheme: 'dark'`，zh-CN 根 locale，favicon/品牌复用 `apps/electron/resources/stair/icon.svg`
   - `custom.css`：中文优先字体栈（PingFang SC / Microsoft YaHei 回退）、zcode 式中性暗色调、排版密度调整
   - 自定义组件：`NextSteps.astro`（3 卡片）、`Screenshot.astro`（占位框：约定真图路径 + zcode 式日期命名规范，后续替换即出真图）；asides/tabs/cards 用 Starlight 内置
   - 根脚本：`docs:dev`（lsof 清理 5176 后启动）/ `docs:build` / `docs:preview`；顺手清掉现有 dangling 的 mintlify `docs:dev` 脚本（`apps/online-docs` 目录不存在）
2. **样板 3 页**：welcome / citations-notes / reading-loop，严格套模板 + humanizer 终检 → **停下来给你过目**（观感、口径、密度三件事确认后）
3. **批量补全其余 15 页**，事实源映射：welcome 理念 ← `stair-product-ideas.md`；功能页机制 ← `stair-rebuild-plan.md` 各阶段；限制 ← regression 各模块 case + §4.6；架构组 ← rebuild-plan 阶段 0/9 + 路径协议内容
4. **质量门禁**
   - 中文搜索实测（Pagefind 对 stair 术语的分词质量），不达标换搜索方案
   - `validate.yml` 加独立 `docs` job（bun install → astro build），不碰现有 `validate:ci` 硬编码列表
5. **交付**：`bun run docs:dev` → http://localhost:5176，附整站构建通过说明

- `bun run docs:build` 通过；18 页全部存在且套模板；中文搜索能命中"引用""白板"等术语；每页通过 humanizer 终检（无事实漂移、无模式簇残留）；三页样板经你确认。
